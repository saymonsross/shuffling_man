# AGENTS.md

Универсальные инструкции для всех coding-агентов, работающих с этим репозиторием.

## Правило: проверяй 7dots перед реализацией

**ОБЯЗАТЕЛЬНО** перед реализацией любой функциональности в `.rpy`-файлах — использовать skill `7dots-reference` (`.agents/skills/7dots-reference/SKILL.md`) и убедиться, что нужного нет в библиотеке. Это касается показа и скрытия спрайтов, аудио, переходов, движения персонажей, эффектов размытия/цвета/яркости, UI-элементов, анимаций и управления диалогом. Если функция есть в 7dots — используй её, не дублируй.

## Project Overview

**Шаркающий человек (Shuffling Man)** — психологический хоррор на движке Ren'Py 8.5.3. Нарратив от ненадёжного рассказчика (Марина): история о распаде семьи и психическом расстройстве. Визуальная реальность постепенно разрушается — от "идеализированной" версии событий до мрачной правды. Сеттинг: Москва, начало 2000-х.

## Architecture

### File Organization

```
game/
├── script.rpy       — точка входа; прыгает на титры пролога
├── options.rpy      — конфиг движка (имя, звук, переходы)
├── gui.rpy          — визуальные параметры UI (1920×1080, акцент #cc0000)
├── screens.rpy      — базовые экраны интерфейса (диалог, меню, сохранения)
├── fx_config.yaml   — сквозные параметры визуальных эффектов (реестр — common/fx_config.rpy)
├── dev/             — dev-инструменты, из дистрибутива вырезаны
│   ├── dev_hub/          — Dev Hub (F12): запуск инструментов, хоткеи, статус
│   ├── fx_tuner/         — FX Tuner (F10): эффекты вживую → fx_config.yaml
│   ├── position_tuner/  — Position Tuner (F9), README.ru.md / README.en.md
│   ├── scene_navigation/ — dev-навигация по сценам и превью
│   ├── testcases.rpy     — тестовые сценарии Ren'Py, testsuite global и его хуки
│   └── *_regression_tests.rpy — регрессионные тесты подсистем
└── libs/
    ├── libs.txt     — заставляет Ren'Py загружать libs/ перед остальными файлами
    └── 7dots.rpy    — расширенная библиотека утилит (загружается до всего)
```

Черновые ассеты (PSD/JPG) живут вне репозитория: `../shuffling_man_assets/Черновик/`.

### Load Order

Ren'Py загружает файлы в следующем порядке благодаря `libs/libs.txt`:

1. `libs/7dots.rpy` (init приоритеты -999 → 999)
2. `gui.rpy` (offset -2)
3. `screens.rpy` (offset -1)
4. `script.rpy` и остальные `.rpy`-файлы

### 7dots Library

`game/libs/7dots.rpy` — основной инструментарий проекта. Покрывает: аудио (mplay/splay/vplay/sfxplay), трансформации (позиции, масштаб, цвет, силуэты, 3D-повороты, анимации), систему времён суток, управление диалогом (dismiss_on/off), спрайт-утилиты, переходы (Flash, TurnPage).

**Перед реализацией любой функциональности используй skill `7dots-reference`** — полный справочник всех функций с примерами.

## Подключаемые правила и skills

- `.agents/skills/*/SKILL.md` следует открытой спецификации Agent Skills. Если задача совпадает с `description` skill или пользователь назвал его явно, прочитай `SKILL.md` целиком и следуй ему доступными инструментами.
- `.agents/rules/*.md` — проектное расширение для всех агентов. Перед правкой файла прочитай правила, чьи `paths` в YAML-frontmatter покрывают этот файл; правило без `paths` применяется ко всему репозиторию. Пути считаются относительно корня репозитория, разделитель — `/`, `**` означает ноль или больше уровней каталогов.
- `.agents/plans/*.md` — исторические планы реализации. Они не являются активными инструкциями и могут описывать уже изменившиеся пути или решения.
- `.claude/settings*.json` и тонкие `.claude/rules`/`.claude/skills`-адаптеры нужны только клиенту Claude. Канонические тексты проектных правил и skills находятся исключительно в `.agents`.

Внутри репозиторного контракта `AGENTS.md` и подходящие `.agents/rules` имеют приоритет над defaults из skills. Skill уточняет способ выполнения конкретной задачи, но не отменяет проектные ограничения. Прямые инструкции пользователя и правила среды агента сохраняют свой обычный более высокий приоритет.

### Проектные skills

- `7dots-reference` — обязательная проверка перед любой реализацией в `.rpy`; `.agents/skills/7dots-reference/SKILL.md`.
- `renpy-atl-layeredimage` — ATL, transform, анимации и LayeredImage; `.agents/skills/renpy-atl-layeredimage/SKILL.md`.
- `renpy-minigame` — мини-игры и интерактивы: архитектура цикла, состояние, ввод, время, пропуск/откат/сейв, доступность и регрессионные тесты; `.agents/skills/renpy-minigame/SKILL.md`. Обязателен перед реализацией или правкой любой мини-игры, после проверки `7dots-reference`; для мини-игр имеет приоритет над `renpy-vn-toolkit`.
- `renpy-vn-toolkit` — готовые модули и паттерны Ren'Py/7dots; `.agents/skills/renpy-vn-toolkit/SKILL.md`. Использовать только для конкретного отсутствующего модуля после проверки `7dots-reference`; перед переносом проверять зависимости, побочные эффекты и целевые пути. Модули мини-игр (BALANCE, pipes, dungeon) — только справочник механик: строить мини-игру по `renpy-minigame`. В этом репозитории его `sources/core/7DOTS.rpy` — только справочная upstream-копия: не копировать её в `game/`, не создавать вторую библиотеку и не перезаписывать `game/libs/7dots.rpy`.

### Файлы и папки

- Имена файлов и папок — строго на английском, нижний регистр, слова через `_`.
- Сценарные `.rpy` внутри папок глав — максимум на одном уровне вложенности. Технические деревья `images/`, `audio/`, `dev/`, `gui/`, `libs/` и `tl/` могут иметь нужную им вложенность.
- Папки этапов повествования — с числовым префиксом сортировки (номер главы только в префиксе, без дублирования): `0_prologue/`, `1_chapter/`, `2_chapter/`, `3_chapter/`, `4_endings/`. Запас в нумерации не оставлять, `00` не использовать. Префикс — только для отображения в дереве; порядок загрузки — через `libs/libs.txt`. Имена файлов префиксов не получают.
- Имена файлов избыточны и полностью дублируют структуру повествования (файл идентифицируется по имени без учёта пути):
  - Сцены: `0_prologue/prologue_scene_1.rpy`, `1_chapter/chapter_1_scene_2.rpy`
  - Концовки: `4_endings/ending_1.rpy`
  - Мини-игры: в папке своей главы — `2_chapter/chapter_2_scene_3_minigame_piano_1.rpy`
- Код делить на файлы аккуратно, без избыточного дробления.
- Переиспользуемый код (шейдеры, трансформы, экраны, утилиты — всё, что нужно более чем одной сцене) — в `game/common/`, тематическими файлами (`shaders.rpy`, `transforms.rpy`, …). В папках глав — только код конкретных сцен; специфика — параметрами, не копиями кода.
- При удалении/переименовании `.rpy` удалять осиротевший `.rpyc`.

### Код

- `define` — константы (персонажи, transforms); `default` — все изменяемые игровые переменные (флаги, счётчики). Игровые флаги никогда не инициализировать через `$` или `init python`.
- Предпочитать операторы Ren'Py (`show`, `while`, `menu`) их Python-эквивалентам — их проверяет lint и предсказывает движок. Для аудио действует отдельное правило об обязательных обёртках 7dots ниже.
- Глобальные лейблы уникальны и дублируют структуру по той же схеме, что имена файлов: `chapter_1_scene_2`, `prologue_scene_1`, `ending_1`; точки внутри сцены — локальные лейблы (`.loop`).
- Сцены связаны цепочкой `jump`: каждая сцена в конце прыгает на следующую, последняя делает `return` в главное меню. `call` — только для подпрограмм (мини-игры, вставки), не для перехода между сценами.
- У `call` в релизе должен быть `from`-клаус.
- Все строки интерфейса — в `_("...")`. Игра пишется на русском (язык None).
- Пиксельные значения в позиционных свойствах (`pos`, `xpos`, `anchor` и т.п.) — только `int`: `float` Ren'Py трактует как нормализованную долю экрана/контейнера. Нормализованные координаты `0.0..1.0`, например `anchor (0.5, 0.5)`, допустимы. Результаты Python-вычислений для пикселей приводить через `int(round(...))`.
- В сценах числа (позиции в px, якоря, углы, тайминги, зумы, zorder, громкости) пишутся прямо в `show ... at`, ATL и вызовах — без `define`-констант. Константа остаётся, только если значение читает другой файл (мини-игра, тест, `common/`). Мини-игры и `common/` держат свои параметры константами: их читают логика и тесты. Подобрать числа помогает Position Tuner — `F9` в dev-режиме: обводит спрайты по контуру, показывает их точные pos/anchor/rotate/zoom прямо из трансформов сцены, даёт подвигать призрак мышью, стрелками, `Tab` и `[`/`]`, кладёт готовый ATL или вызов `placed(...)` в буфер, а по `Ctrl+S` сам переписывает литералы в `show ... at placed(...)`. Подробности — `game/dev/position_tuner/README.ru.md`.
- Параметры визуальных эффектов, которые подбираются вживую, объявляются через `fx_param("группа.имя", default, lo, hi, doc=...)` рядом с эффектом и читаются `fx_cfg(...)`; значения — `game/fx_config.yaml`, правка — FX Tuner (`F10`, dev). Это настройка проекта, не игровое состояние: интенсивность по сюжету — отдельной `default`-переменной сцены (пример — `fx_posterize_strength`). У зерна (`noise.*`) сюжетной интенсивности нет: оно одно и постоянно на всю игру.
- Состояние function-трансформов — только в `_fx_state` (`common/camera_fx.rpy`) под уникальным ключом, не в атрибутах `trans` и без сброса по `st ≈ 0` — иначе рывки эффекта на кликах и стыках сцен. Полное правило — `.agents/rules/function-transform-state.md`.
- `rotate`/`zoom` с якорным позиционированием требует `transform_anchor True`. Полное правило — `.agents/rules/rotate-transform-anchor.md`.
- Сцены/интерактивы без развилки сюжета и влияния на состояние игры — пропускаемые: реальный интерактив (`call screen` с ожиданием клика) оборачивать в `if not renpy.is_skipping():`, чтобы Ctrl/«Пропуск» проходили его насквозь. Полное правило — `.agents/rules/skippable-scenes.md`.
- Выборы — через `menu` с экраном: сценовые кнопки на картинке — `menu(screen="scene_choice")`, параметры кнопки — аргументами пункта (`"Зажечь свет" (pos=(475, 530), size=(330, 165)):`), не тегами в подписи; ответы в разговоре — `menu(screen="textbox")`, внутри окна диалога.
- Комментарии и docstring оставлять только для сюжета, развилок и неочевидных инвариантов; не пересказывать код и не писать учебные пояснения. Полное правило — `.agents/rules/comments.md` и README, раздел «Комментарии и docstring».

### Сценарный текст

- **Неприкосновенен**: формулировки, порядок слов, орфографию и пунктуацию не менять — ни в `docs/`, ни в репликах `.rpy`. Опечатки — сообщать автору, не исправлять. Исключение — только техническое размещение/перемещение текста (например, добавить переносы), содержимое символ в символ сохраняется. Полное правило — `.agents/rules/scenario_text_immutable.md`.

### Мультиязычность (подробно — README, «Мультиязычность»)

- Каждая видимая игроку литеральная строка (экраны, кнопки, `Character(_("..."))`, `renpy.notify`, мини-игры) — в `_("...")`.
- Строки не склеивать — подстановки `[var]`; переведённое значение — `[var!t]`; одинаковые строки с разным смыслом — `{#контекст}`.
- Логика сравнивает ключи, не отображаемый текст; в сейвы/persistent — ключи, не строки.
- Мини-игры: текст не «запекать» в картинки (иначе — вариант файла в `game/tl/<язык>/...`); верстать с запасом по ширине; служебные лейблы — с `hide`.
- Шрифты только через `gui.text_font`/стили; на язык — `translate <язык> python`/`style`-блоки без побочных эффектов.

### Ассеты

- Изображения — `game/images/`, имена в нижнем регистре латиницей, формат «тег атрибут» через пробел (исключение из правила `_`): `marina sad.png`, `bg kitchen day.jpg`. Многословные тег/атрибут — слитно через `_`: `prologue dark_room.jpg`. Полноэкранные кадры сцены — общий тег части + атрибут-имя (`prologue head.jpg`); анимируемые объекты — уникальный тег объекта + атрибуты-анимации (`prologue_hand_right write.png`).
- Подпапки в `game/images/` обязательны: по главам (`0_prologue/`, `1_chapter/`, …, `4_endings/`), при необходимости — по сценам; сквозные ассеты (персонажи, UI) — в `common/`. Имя образа берётся из имени файла, путь движок игнорирует → имена уникальны во всём `game/images/`.
- Аудио — в `game/audio/`, имена в нижнем регистре, слова через `_`, без пробелов и дефисов.

### Аудио: система каналов

`game/common/audio_manager.rpy` управляет тремя линиями (`music`/`voice`/`sfx`), по 5 каналов на каждую. Сценарии используют обёртки 7dots (`mplay`/`splay`/`sfxplay`/`vplay`): они направлены в пул, поддерживают слои `tag`, наложение `overlap` и громкость `volume`. Голые `play`/`stop` в сценариях не использовать. Для полного пути, остановки линии или управления отдельным handle есть `sm_audio_*`. Контракт и примеры — `docs/03_audio_system.md`. `vplay` — ручное воспроизведение; встроенные voice/auto_voice, повторы реплик и ожидание голоса этим пулом не реализованы.
