# RMB Editor

Отправляет запрос Claude прямо из запущенной игры. `Shift`+правый клик по
объекту ставит кадр на паузу и открывает поле ввода; по `Enter` в VS Code
открывается новая вкладка чата Claude Code, в которой уже стоят ваш текст и
контекст клика: что было под курсором, где это в коде, где стоит сценарий и
как выглядел кадр.

*English version: [README.en.md](README.en.md)*

---

## Как пользоваться

1. Запустите игру в dev-режиме; VS Code с проектом открыт.
2. Зажмите `Shift` и кликните правой кнопкой по спрайту, кнопке, детали
   мини-игры или пустому месту. Работает в сцене, в мини-игре, в главном и
   игровом меню.
3. Наберите, что сделать, и нажмите `Enter`.
4. VS Code выходит вперёд с новой вкладкой Claude, текст подставлен в поле
   ввода. Нажмите `Enter` ещё раз — уже в VS Code. Автоотправки у расширения
   нет.

| Клавиша | Действие |
|---|---|
| `Shift`+ПКМ | открыть поле |
| `Enter` | отправить во вкладку VS Code |
| `Shift+Enter` | новая строка |
| `Ctrl+V` | вставить текст из буфера |
| `Esc` | закрыть без отправки |

`Enter` с пустым полем открывает вкладку с одним контекстом — промпт можно
набрать уже в VS Code. Правая кнопка без `Shift` работает как обычно.

В Dev Hub (`F12`) есть строка **RMB Editor**: она открывает поле без точки
клика — в запрос уйдут позиция сценария, экраны и скриншот.

### Файлы

Бросьте файл из Проводника на окно игры — он прикрепится к запросу. Если поле
закрыто, оно откроется; если открыто, файл добавится в список над полем.
Кнопка `×` убирает вложение. В запрос уходит путь, сам файл не копируется и
не меняется.

Бросок означает «прикрепить», а не «сюда»: место в сцене задаётся кликом или
текстом. Если поле открыто у нижнего края экрана, панель растёт вверх.

## Пауза

Пока поле открыто, игра стоит так же, как под игровым меню: сценарий не идёт,
экраны игры и их таймеры не работают, ввод до игры не доходит. На экране —
застывший снимок момента клика.

- Звук во время паузы продолжает играть.
- Время не останавливается. После закрытия поля ожидания и анимации ведут
  себя так, будто время паузы прошло: `pause` с истёкшим таймаутом завершится
  сразу, ATL окажется дальше по времени.
- Переход (`with`), шедший в момент клика, отменяется.
- Сквозные эффекты слоёв из `config.layer_transforms` (параллакс, постеризация)
  продолжают считаться, как и под игровым меню; камера сцены и сами спрайты под
  снимком не исполняются.

## Что получает Claude

В поле ввода вкладки:

```
<ваш текст>

Поймано в игре: prologue_dark_room · game/0_prologue/prologue_scene.rpy:95
Файлы:
- D:\SoundAssets\door_creak.wav
Контекст и скриншот: .rmb_editor/req_20260930_183344_055/request.md
```

Если текст с вложениями не помещается в ссылку (`RMB_URL_MAX`), в поле ввода
попадает только указание прочитать файл запроса; сам текст целиком лежит в
файле.

Папка запроса `.rmb_editor/req_<дата>_<время>_<мс>/` в корне проекта:

| Файл | Содержимое |
|---|---|
| `request.md` | текст, вложения и контекст клика |
| `shot.png` | кадр без поля ввода, в размере окна игры |

Контекст клика в `request.md`:

- точка в координатах игры 1920×1080 и та же точка в пикселях скриншота;
- спрайты сцены под точкой: тег с атрибутами, слой, pos/anchor/rotate/zoom
  как в коде и строки `show`/`scene` этого тега в сценарных файлах;
- элементы экранов под точкой: экран, тип, видимый текст, размер и
  файл:строка определения;
- позиция сценария, лейбл и показанные экраны.

Хранятся последние 10 запросов (`RMB_KEEP`), старые удаляются при создании
нового. Папка не попадает ни в git, ни в сборку. `Esc` удаляет папку
отменённого запроса.

## Ограничения

- **Попадание по спрайту** считается по прямоугольнику нарисованного
  спрайта — с учётом камеры и параллакса, но без учёта прозрачности и
  перекрытия. В запрос попадают все спрайты, чей прямоугольник накрывает
  точку. В главном и игровом меню спрайты не собираются.
- **Элементы экранов** называются по оператору экрана, в котором описаны.
  Содержимое, нарисованное одним собственным displayable, неразличимо.
- **Вставка из буфера** склеивает многострочный текст в одну строку — это
  поведение `input` Ren'Py. Перенос ставится `Shift+Enter`; длинные вставки
  удобнее делать уже во вкладке VS Code.
- **Несколько окон VS Code.** Ссылка приходит в последнее активное окно; если
  открыт другой проект, вкладка появится в нём.
- **Перетаскивание после первого появления инструмента** может потребовать
  полного перезапуска игры: список принимаемых событий окна читается один раз
  при запуске.
- **Перезагрузка скриптов при открытом поле.** Поле возвращается с тем же
  текстом, вложениями и кадром. Позиция игры восстанавливается так же, как
  при обычной `Shift+R`.
- **Размер папки запросов.** Скриншот в размере окна весит несколько
  мегабайт; десять запросов — десятки мегабайт.
- Инструмент рассчитан на Windows: ссылку открывает `os.startfile`.

## Устройство

- `rmb_editor.rpy` — сбор контекста клика, файл запроса, ссылка.
- `rmb_editor_ui.rpy` — перехват жеста и броска файла, пауза, поле ввода.

Поле ввода живёт в новом контексте Ren'Py, как игровое меню: это и даёт
паузу. Фоном показан скриншот, снятый до открытия поля. Данные запроса лежат
в `renpy.session` и не попадают в сейвы и rollback.

Параметры — константы `RMB_*` в начале обоих файлов. Экраны, которые не
должны попадать в контекст клика, перечислены в `RMB_SKIP_SCREENS`.

Тесты — `game/dev/rmb_editor_regression_tests.rpy`. Под тестами настоящая
ссылка не открывается.
