# Position Tuner

Инструмент осмотра и подбора координат прямо в запущенной игре на Ren'Py.
Открывается в любой сцене, обводит спрайты по контуру и показывает их точные
параметры — позицию, точку привязки, угол наклона, зум, размер картинки и её
габариты на экране. Выбранный спрайт можно подвинуть, повернуть и сменить ему
точку привязки, чтобы подобрать числа и скопировать их в код.

**Инструмент ничего не записывает и сцену не меняет.** Он читает живые
трансформы сцены и считает; числа переносятся в код руками, через буфер обмена.

*English version: [README.en.md](README.en.md)*

## Что он показывает

Для каждого спрайта на экране:

| Значение | Откуда |
|---|---|
| `pos` | позиция из трансформа сцены, в пикселях |
| `anchor` | точка привязки, в долях стороны спрайта |
| `rotate` | **угол наклона в градусах** (`—`, если поворота нет) |
| `zoom` | масштаб |
| `картинка` | собственный размер изображения, px |
| `на экране` | итоговый прямоугольник с учётом зума и поворота |

Все спрайты обводятся тусклой рамкой сразу — видна вся композиция и
перекрытия слоёв. Выбранный обводится ярко, причём контур **повторяет наклон**:
это не axis-aligned коробка, а повёрнутый вместе со спрайтом прямоугольник.
Через точку привязки бьют направляющие во весь экран, сама точка помечена
крестиком — видно, вокруг чего спрайт вращается.

## Установка в проект

1. Скопировать папку `position_tuner/` в `game/dev/` своего проекта.
2. Исключить dev-папку из дистрибутива — в `options.rpy`, внутри `init python`
   рядом с остальными `build.classify`:

   ```renpy
   build.classify('game/dev/**', None)
   ```

3. Запустить игру в dev-режиме и нажать **F9**.

Больше ничего не требуется: никаких файлов данных, никакой настройки проекта.
Инструмент использует только публичный API Ren'Py, не зависит от сторонних
библиотек и не тянет картинки из `gui/`.

### Проверка, что в сборку не попало

```
renpy.sh launcher distribute --dest /tmp/dist --package pc --format zip <проект>
```

В получившемся архиве не должно быть ни одного файла из `game/dev/`.

## Работа

| Действие | Как |
|---|---|
| Открыть / закрыть | **F9**, ещё **Esc** на закрытие |
| Выбрать спрайт | клик по нему на сцене или по строке в списке |
| Двигать | тащить мышью (вне панели) |
| Точно двигать | **стрелки** ±1 px, **Shift+стрелки** ±10 px |
| Наклон | **[** и **]** ±1°, с **Shift** ±15° |
| Точка привязки | **Tab** вперёд, **Shift+Tab** назад |
| Отменить / вернуть | **Ctrl+Z** / **Ctrl+Shift+Z** (или Ctrl+Y) |
| Вернуть значения сцены | **R** или кнопка «Сбросить» |
| Скопировать | **Ctrl+C** или кнопки |
| Убрать панель с дороги | **H**, или кнопки «вправо»/«влево» |

Клик мышью берёт спрайт под курсором; если их несколько, выбирается самый
мелкий — так предмет не перехватывается фоном под ним.

Пока значения совпадают со сценой, призрак не рисуется — только контур
и цифры. Как только вы что-то сдвинули, появляется полупрозрачная копия
в новом положении, а панель дополнительно показывает строку «в сцене: …»
с исходными значениями.

### Что копируется

**Копировать ATL** — блок для вставки прямо в сцену:

```
anchor (0.5, 0.5)
pos (1264, 431)
rotate 80.0
```

**Копировать вызов** — вызов трансформа по шаблону:

```
at placed((1264, 431), (0.5, 0.5), 80.0)
```

Шаблон задаётся одной строкой в начале `position_tuner.rpy`:

```renpy
define -30 PT_CALL_TEMPLATE = "at placed({pos}, {anchor}, {angle})"
```

Подстановки — `{pos}`, `{anchor}`, `{angle}`. Под свой набор трансформов
меняется здесь же.

### После вставки в код

Нажмите **Shift+R**. Ren'Py перезагрузит скрипт, но уже показанный спрайт
останется на месте: трансформ получает координату в момент `show` и запоминает
её, а перезагрузка восстанавливает сцену из последнего чекпоинта, который стоит
на реплике *после* `show`. Чтобы увидеть результат, проиграйте сцену заново —
откатитесь колесом мыши за момент показа и пройдите вперёд.

Поэтому подгонять удобнее в песочнице: короткий лейбл, который показывает
нужные спрайты и сразу висит на паузе (пример — `dev_position_sandbox`
в `game/dev/dev_utils.rpy`). Проиграть его заново — одна клавиша.

## Ограничения

- **Камера.** Контуры и призрак рисуются в базовых координатах экрана и не
  повторяют `camera`-трансформы сцены (зум, наклон кадра). Числа
  при этом верные — именно их ждёт `pos`, — но картинка может разъезжаться
  с тем, что видно. Для точной работы используйте песочницу без камеры.
  Параллакс слоя `master` (`common/parallax.rpy`), пока тюнер открыт, гасится.
- **Анимация.** У движущегося спрайта показания меняются каждый кадр — это
  честно, но подбирать по ним нечего. Останавливайте сцену на нужном кадре.
- **Экзотическое позиционирование.** `xalign`/`xcenter`/`xoffset` и прочее
  приводится к паре `pos` + `anchor`; если у спрайта вообще нет трансформа,
  значения берутся из габаритов на экране, и панель об этом пишет.

## Настройки

Все в начале `position_tuner.rpy`:

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `PT_UNDO_LIMIT` | `1000` | глубина стека отмены |
| `PT_COALESCE_T` | `0.35` | за сколько секунд серия правок склеивается в один шаг |
| `PT_STEP` / `PT_STEP_BIG` | `1` / `10` | шаг стрелок, px |
| `PT_STEP_ANGLE` / `PT_STEP_ANGLE_BIG` | `1.0` / `15.0` | шаг наклона, градусы |
| `PT_ANCHORS` | 9 якорей | что перебирает Tab |
| `PT_GHOST_ALPHA` | `0.55` | прозрачность призрака |
| `PT_CALL_TEMPLATE` | `at placed(…)` | шаблон кнопки «Копировать вызов» |
| `PT_HOTKEY` | `"K_F9"` | клавиша открытия |
| `PT_COLOR_BOX` / `PT_COLOR_DIM` / `PT_COLOR_GUIDE` / `PT_COLOR_MARK` | | цвета контуров и меток |

## Как устроено

| Файл | Что внутри |
|---|---|
| `position_tuner.rpy` | настройки, чтение сцены, модель, стек отмены, слои отрисовки и мыши |
| `position_tuner_ui.rpy` | экран, хоткеи, стили |

Четыре места, где легко ошибиться при доработке:

1. **`renpy.get_at_list` отдаёт шаблон трансформа, а не живой экземпляр.**
   У шаблона все свойства пустые — ATL-блок на нём не исполнялся, и `rotate`
   там всегда `None`. Реальные значения есть только у объекта из
   `renpy.scene_lists().layers[layer]`.
2. **`absolute` — это подкласс `float`.** Проверять его нужно раньше `float`,
   иначе пиксельные `400.0` будут поняты как 400 ширин экрана.
3. **Ren'Py кэширует рендер.** Модель меняется мимо экрана (стрелки, Tab,
   отмена), поэтому слой отрисовки в `render()` сам просит перерисовку через
   `renpy.redraw`. Без этого контур остаётся на старом месте.
4. **Порядок детей экрана двойной.** Рисуются с начала, а события Ren'Py
   отдаёт с конца. Поэтому контуры добавлены первыми (они под панелью),
   а слой захвата мыши — последним (события достаются ему раньше кнопок);
   клики по площади панели он пропускает дальше.

Наклонённый контур строится не вручную по четырём углам, а тем же трансформом,
что и сам спрайт: прямоугольник-рамка размером ровно с картинку заворачивается
в `Transform(pos, anchor, rotate, transform_anchor=True)`. Поэтому он ложится
на спрайт точно, при любом угле и якоре.

Состояние инструмента лежит в объекте от `python_object`, а не в обычных
переменных store, — оно не попадает ни в rollback, ни в сейвы игрока.
