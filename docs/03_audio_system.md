# Аудиосистема

Реализация: `game/common/audio_manager.rpy`. Обёртки в `game/libs/7dots.rpy` сохраняют прежние имена, позиционные аргументы, каталоги и расширение `.ogg`. Текущие вызовы в сценах работают через пул без переписывания сцен.

## Линии и воспроизведение

Три линии содержат по пять обычных каналов Ren'Py: `sm_music_0..4`, `sm_voice_0..4`, `sm_sfx_0..4`. Они привязаны к штатным микшерам `music`, `voice`, `sfx`, поэтому работают существующие настройки громкости и mute. Mute сохраняет ход воспроизведения, а unmute не начинает фон заново.

| Обёртка | Линия / группа | По умолчанию |
| --- | --- | --- |
| `mplay`, `mreplay`, `rndplay`, `fnplay` | music / music | Зацикленная музыка, замена слоя |
| `splay` | sfx / audio | Короткие эффекты с наложением |
| `sndplay` | sfx / sound | Короткий эффект, замена слоя |
| `sfxplay` | sfx / effect | Зацикленный фон, замена слоя |
| `vplay` | voice / voice | Ручной голос, замена слоя, без зацикливания |

`tag` именует слой внутри группы. Вызов с тем же `tag` заменяет этот слой; другой `tag` добавляет независимый слой. Без `tag` используется общий слой этой группы. `overlap=True` разрешает наложение даже внутри одного слоя; у `splay` оно включено по умолчанию. Список файлов в `mplay`/`splay`/`sndplay`/`fnplay` — последовательный плейлист на одном канале, не одновременный запуск списка.

При замене новый звук начинает играть на свободном канале с `fadein`, прежний затухает на своём с `fadeout`. Поэтому кроссфейд действительно перекрывает треки. `mplay` сохраняет прежнее поведение перезапуска; `if_changed=True` в `mplay`/`fnplay` сохраняет текущий трек, если он входит в новый плейлист, и обновляет очередь, loop и громкость. `mreplay` всегда перезапускает.

```renpy
$ mplay("room_theme", tag="score", volume=0.65)
$ sfxplay("rain", tag="weather", volume=0.4)
$ sfxplay("clock", tag="clock", volume=0.2)
$ splay("door_click")
$ mplay("danger_theme", tag="score", fadein=2.0, fadeout=2.0)
$ sfxstop(tag="weather", fadeout=1.0)
```

Имена треков в примерах условные; система не добавляет музыкальное оформление сцен или новые звуковые ассеты. `ext="mp3"`/`"opus"`/`"wav"` выбирает другое расширение.

## Остановка и громкость

Каждый успешный play возвращает handle `(физический_канал, номер_запуска)`; пропущенный запуск возвращает `None`. Явное `stop(handle=None)` ничего не останавливает. После повторного использования канала старый handle не может остановить или изменить новый звук. Handle действует в контексте игры; для хранения между репликами объявлять переменную через `default`.

```renpy
default door_sound = None

label audio_example:
    $ door_sound = splay("door_creak", volume=0.5)
    $ sm_audio_set_volume(door_sound, 0.2, delay=0.5)
    $ sm_audio_stop(handle=door_sound, fadeout=0.3)
    return
```

- `mstop`, `sstop`, `sndstop`, `sfxstop`, `vstop` останавливают только свою группу. Например, `sstop()` убирает короткие `splay`, сохраняя фон от `sfxplay`.
- Аргументы `tag=` и `handle=` сужают выбор остановки. Без них останавливается вся группа, включая её затухающие звуки.
- `sm_audio_stop(line="sfx", fadeout=1.0)` останавливает все группы линии эффектов; без `line` — все три линии пула.
- `sm_audio_set_volume(handle, volume, delay=0)` меняет громкость живого звука и возвращает `False` для устаревшего или завершённого handle. Диапазон громкости `0..SM_AUDIO_MAX_VOLUME` (10.0), времена неотрицательные и конечные.
- `sm_audio_set_pan(handle, pan, delay=0)` смещает живой звук в стерео: `-1` — только левый канал, `0` — по центру, `1` — только правый. Панорама принадлежит звуку: новый звук на том же канале играет по центру. Устаревший или завершённый handle возвращает `False`.
- Громкость выше `1.0` — усиление: `volume=1.4` играет трек на полной громкости микшера и добавляет линейный gain ×1.4 поверх. Микшер жёстко режет выход на ±1.0, поэтому громкий исходник при усилении клиппует; усиливать стоит только тихие треки. Часть до `1.0` идёт штатной громкостью канала (участвует в `delay`-затухании, сохраняется движком), излишек — через gain канала, который меняется мгновенно и восстанавливается пулом из своих записей после load, rollback и смены контекста.
- `sm_audio_set_filter(handle, audio_filter, duration=0.016)` плавно применяет штатный фильтр Ren'Py или цепочку фильтров к текущему звуку и его loop, сохраняя позицию воспроизведения. `None` снимает обработку; устаревший, остановленный или завершённый handle возвращает `False`. При новом запуске на переиспользованном канале обработка сбрасывается, а `if_changed=True` сохраняет её вместе с продолжающимся звуком. Для нарастающего эффекта задавать конечную цепочку один раз с нужной длительностью перехода.
- `sm_audio_stop_tail(handle, cut=0.2, fadeout=None, tail=6.0)` останавливает звук, оставляя хвост его фильтра; обычная остановка гасит звук вместе с хвостом. `cut` — за сколько секунд гаснет сам звук. `fadeout` — за сколько гаснет его посыл в эхо: эхо звука тянется дольше него самого (по умолчанию равен `cut`); действует, когда цепочка фильтров кончается `Reverb` или `WetDry`, иначе весь звук гаснет за `fadeout`. `tail` — секунды от вызова до освобождения канала, запас на хвост. Звук без фильтра просто гаснет за `cut`; устаревший или остановленный handle возвращает `False`.
- `msave()`/`mrestore()` сохраняют и восстанавливают имя последнего активного музыкального трека, как прежний helper; это не снимок всех музыкальных слоёв и не сохранение позиции.
- Action-версии `MPlay`, `SPlay`, `SFXPlay`, `VPlay`, `FNPlay`, `MStop`, `SStop`, `SFXStop`, `VStop` используют тот же пул. ATL helpers `s_play`/`sfx_play` также идут через него.

Для полного пути используется `sm_audio_play(files, line="sfx", tag=None, loop=False, fadein=0, fadeout=0, volume=1.0, overlap=False, if_changed=False)`. У этого API наложение включается явно. Полный путь можно также передать в `fnplay`. Явно переданный пользовательский `channel`, отсутствующий среди логических имён `music`/`voice`/`sfx`/`audio`/`sound`/`effect`, продолжает работать как обычный канал Ren'Py и находится вне лимита пула.

## Предел пяти каналов

Затухающий трек занимает канал до окончания fade. Выбор при новом запуске:

1. Свободный или уже завершившийся канал.
2. Самый старый затухающий звук.
3. Самый старый короткий звук.
4. Новый loop может вытеснить самый старый loop. Короткий звук при пяти занятых loop пропускается и возвращает `None`; явная замена собственного слоя разрешена.

При вытеснении звук прекращается сразу: шестой одновременный голос физически невозможен, а ожидание fade на том же канале создало бы задержку запуска. Обычные кроссфейды при наличии свободного канала остаются плавными.

## Голос: реплики и ручная линия

В демо озвучки нет: `config.has_voice = False`, операторов `voice` в сценах и файлов в `game/audio/voice/` нет (бэкап записей пролога — у автора). Инфраструктура ниже остаётся и включается `config.has_voice = True`.

Озвучка реплик — штатный voice Ren'Py: `voice "file"`, `voice sustain`, `config.auto_voice`, теги, mute и громкость персонажей, повтор последней реплики (`VoiceReplay`), ожидание голоса при автопереходе. Воспроизведение идёт в линию `voice` отдельным слоем `SM_VOICE_TAG` (`game/common/voice.rpy`). Любая остановка реплики, кроме пропуска, гаснет за `SM_VOICE_FADEOUT`; следующая реплика начинается сразу, поверх затухания. При mute голоса автопереход не ждёт реплику. На канал реплики ставится `Reverb` с параметрами группы `voice_reverb` в `game/fx_config.yaml` (FX Tuner, F10); файлы озвучки остаются сухими.

`vplay` — ручная voice-линия для звукового дизайна вне реплик; голос играет до конца, замены или `vstop`. `vplay` без `tag` реплику не заменяет, а `vstop()` и `sm_audio_stop(line="voice")` без `tag` останавливают и её. `vplay` подчиняется громкости голоса и приглушает self-voicing, пока звучит.

Прямое воспроизведение на штатном канале `voice` (`Play("voice", …)`, `renpy.sound`) идёт мимо пула и не кроссфейдится.

## Сохранения, меню и границы

Снимок распределения каналов хранится в `renpy.context()` и заменяется целиком при изменениях. Он сохраняется и откатывается вместе с контекстом; дочернее игровое меню не меняет распределение родительского контекста.

Ren'Py восстанавливает зацикленные плейлисты при загрузке/rollback. Короткие эффекты не воспроизводятся повторно. Точная позиция звука и незавершённый кроссфейд не восстанавливаются. Все 15 каналов останавливаются при возврате в главное меню. Обычное игровое меню сохраняет фон. Отдельная `config.game_menu_music` пока не настроена: её добавление потребует правила приглушения или остановки фоновой music-линии.

Трек главного меню — исключение из пула: лейбл `main_menu` (`game/main_menu.rpy`) включает его на штатном канале `music`, который обёртки 7dots не видят. `label start` гасит этот канал с затуханием, чтобы трек не звучал поверх игры; `config.main_menu_music` не используется, потому что Ren'Py заново включает его при каждом `full_restart`.

Фильтры сохраняются в штатном аудиоконтексте Ren'Py. Точная фаза перехода между фильтрами и содержимое хвоста реверберации после загрузки не восстанавливаются. В игровом меню фон и его обработка продолжают звучать; фильтр метронома не распространяется на стуки и другие звуки.

`sm_audio_snapshot(line=None)` возвращает диагностические копии записей с group/tag/handle/filenames/loop/volume, флагом `active` и текущим `playing`. `active` описывает запрошенный слой; фактическое воспроизведение проверять по `playing`, поскольку короткий звук мог уже завершиться.

Автоматические проверки — `game/dev/audio_regression_tests.rpy`; запуск вместе с проектом: `powershell -ExecutionPolicy Bypass -File .\tools\check_project.ps1`. Проверки каналов и состояния не заменяют прослушивание конкретных ассетов и подбор их громкости в сценах.
