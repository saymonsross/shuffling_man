# Правило: проверяемое использование Ren'Py MCP

MCP — вспомогательный интерфейс к Ren'Py, а не источник истины о проекте.
Перед работой вызвать `set_project` с абсолютным путём и проверить активный проект.

## Допустимое применение

- Использовать для поиска в документации установленного SDK, навигации по определениям экранов и тестов, запуска конкретного теста и предварительного lint.
- Результаты `run_test` проверять по фактическим `PASSED`/`FAILED`, числу выполненных тестов и assertions. Список определений тестов не равен числу запусков с параметрами.
- Итоговую проверку изменений проводить через `tools/check_project.ps1`: MCP lint не включает проектные строгие флаги, а обёртки запуска не возвращают код завершения как отдельный результат.
- `isError=false` не означает успех Ren'Py: при ошибке компиляции и неизвестном тесте этот флаг оставался ложным. Читать текст ошибок; в JSON-дампе проверять `error` и наличие нужных данных. В проверенном дампе `location.label` был пуст.
- `run_test` ограничен 120 секундами без параметра настройки тайм-аута; полный `global` на этом проекте был прерван. Для длительного прогона использовать штатный скрипт; тайм-аут не считать ни PASS, ни доказательством дефекта игры.

## Подтверждённые ограничения аналитики

- `story_flow_graph` и `find_dead_ends` не учитывают полноценно локальные лейблы, `hide`, динамические переходы и тестовые входы; `call screen` ошибочно разбирается как вызов лейбла `screen`.
- `character_map` и `count_dialogue` принимают технические строки экранов/тестов за диалоги. Статистику сверять с Ren'Py lint и исходниками.
- `music_timeline` не понимает обёртки 7dots (`mplay`, `splay`, `sfxplay`, `vplay`) и проектный аудиопул. Пустой отчёт не доказывает отсутствие звука.
- `find_unused_assets` не распознаёт все вычисляемые пути; кадры `noise_anim_%d.png` используются, хотя попадают в отчёт. По этому отчёту нельзя удалять ассеты без проверки ссылок и runtime.
- Списки экранов, персонажей, лейблов и их использований — подсказки для поиска, не доказательство полноты или отсутствия ссылок.
- Не менять сценарный текст, переходы или имена по автоматическому отчёту без проверки исходников; для рефакторинга сначала просмотреть `dry_run` и учесть правила проекта.
- `validate_script` выдавал 156 сообщений при чистом строгом lint, включая ошибочные `invalid_call` для `screen` и `undefined_character` для `id`/`style`. Это эвристики, не диагностика движка.
- `rename_label` для `chapter_1_scene_1` предлагал только две замены, пропуская `chapter_1_scene_1.tv`, `.cleanup` и строковые ссылки каталога. Автоматически применять такое переименование нельзя: проверить квалифицированные локальные лейблы, Python-строки и тесты.

## Проверки запущенной игры

- Проверять bridge, запись переменных, warp и инструменты, создающие `.rpy`, сначала в отдельной копии текущего проекта с изолированными сохранениями. Не переносить bridge в основную игру как побочный эффект исследования MCP.
- Bridge включает autoreload и меняет его blacklist; учитывать это при сравнении поведения с обычным запуском.
- Запросы к live bridge выполнять последовательно: он использует общие `cmd.json` и `status.json`, без очереди независимых запросов.
- Даже последовательный запрос может получить свежий heartbeat/init вместо своего ответа: сервер проверяет только время, не `action`/ID. После записи переменной и warp отдельно читать ожидаемое значение/позицию/экран; общий `success` и «MCP bridge active» недостаточны.
- Отличать успешный ответ MCP, правильное состояние игры и визуальную проверку. Warp не является прохождением сцены обычным маршрутом.
- `live_get_state` возвращает срез store: коллекции ограничены 50 элементами и глубиной, часть объектов исключена. `current_label` — фактически файл/строка, не гарантированное имя лейбла. Для точной проверки предпочтителен узкий `live_eval`; он поддерживает и `exec`, поэтому считать его потенциально изменяющим состояние.
- `screen_hierarchy` показал дерево главного меню, но поля `style` были пусты; `style_inspector("say_dialogue")` упал с `'list' object is not callable`.
- Скриншот всегда просматривать. `screenshot_scene` для рабочей сцены вернул почти чёрный кадр 320×180 с сообщением об успехе, тогда как `live_screenshot` дал правильный кадр 2880×1620. В текущем MCP изображения упакованы в JSON-текст с base64 вместо нативного image-блока: не печатать этот текст целиком, извлекать изображение или читать созданный PNG.

Наблюдения относятся к локальному `renpy-mcp` 1.1.2 и Ren'Py 8.5.3, проверенным 2026-09-22. После обновления перепроверять ограничения, а не считать их неизменными.

Подробности и границы проверки: `docs/05_renpy_mcp_audit.md`.
