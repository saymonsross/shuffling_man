# Архитектура мини-игры

Как устроить цикл, состояние, вход и выход так, чтобы игра переживала откат, сохранение, пропуск и игровое меню.
Ссылки на движок — страницы `doc/` и модули `renpy/` SDK 8.5.0.

## Одна интеракция за раз

Ren'Py исполняет одну интеракцию (ожидание ввода) за раз: из action, `timer`, `key` или `event()` CDD нельзя
звать `renpy.pause`, `renpy.call_screen`, `renpy.input`, `renpy.confirm` — будет «Cannot start an interaction in
the middle of an interaction». Вложенный диалог внутри мини-игры — только `renpy.invoke_in_new_context(...,
_clear_layers=False)`. Интеракцию завершает первый обработчик, вернувший не-None: `Return(v)` (`Return()` даёт
`True`), `Function` с возвратом, `key`, `timer`, `hovered`, `on`, колбэк Drag, `event()` CDD. Оператор `pause`
значение выбрасывает, `$ x = renpy.pause()` — возвращает.

## Модели цикла

### A. Действие = `call screen` → `Return(ключ)` в Ren'Py-`while`

Экран только показывает и возвращает ключ действия; лейбл засчитывает его, играет звук и решает, что дальше.
`call screen` после интеракции ставит жёсткую контрольную точку, поэтому откат колесом отменяет ровно одно
действие, а загрузка возвращает к началу текущего выбора с уже засчитанными прошлыми. Пропуск, откат и сейв
работают без дополнительного кода. Эталоны — уборка (`chapter_1_scene_1_minigame_cleanup.rpy`) и
`templates/minigame_hotspots.rpy`.

```renpy
while board_outcome is None:
    if not renpy.is_skipping():
        call screen board_screen(_with_none=False)   # кадр остаётся для dissolve
        if _return == "done":
            $ board_finish()
        elif _return is True:                        # SkipOnce позднего пропуска
            $ board_finish(skipped=True)
        elif board_take(_return):
            show screen board_screen                  # растворить исчезнувшую цель
            with Dissolve(0.22)
    else:
        $ board_finish(skipped=True)
```

`with` блокирует ввод на время перехода — растворяй только то, что реально исчезло.

### B. Сценарий-оркестратор этапов

Лейбл ведёт фазы (подход, этапы, итог); каждый этап — свой `call screen` внутри Ren'Py-`while`. Смена моделей
между этапами — `renpy.transition(Dissolve(t), layer="…")` на отдельном слое, чтобы фон не мигал. Так устроены
замки: `game/1_chapter/chapter_1_scene_1_minigame_locks.rpy`.

### C. Реальное время на tick-таймере экрана

Для QTE, шкал, удержания, перетаскивания деталей. Модель — `default`-словарь, её двигает функция-тик:

```renpy
timer 1.0 / 30 repeat True modal True action Function(board_tick, _update_screens=False)
```

- `_update_screens=False`: иначе каждый тик перезапускал бы интеракцию и пересчитывал все экраны.
  `renpy.restart_interaction()` звать только на границах состояния (сменилась фаза, взята деталь).
- Представление — function-трансформы и CDD, которые **только читают** модель.
- Завершение — тик возвращает не-None, или поллинг-проверка через `renpy.end_interaction(v)`.
- `modal True` у таймера: под чужим модальным окном он молчит. Поэтому тик-таймер дублируется в каждом
  модальном экране мини-игры, иначе модель замрёт под ним.
- Часы — `time.perf_counter()` в `NoRollback`-объекте с потолком шага ([time.md](time.md)).
- Граница `call screen` — единица загрузки: экран на серию проще, и загрузка начинает серию заново (каркас QTE);
  экран на раунд сохраняет итоги пройденных раундов ([шкала](blueprints.md#шкала-поймай-момент-и-маятник)).

Каркас с тестами — `templates/minigame_qte.rpy`; полноразмерный пример с захватом указателя — замки.

### D. CDD (`renpy.Displayable`)

Для непрерывной физики, удержания клавиш, множества объектов, собственного ввода. Объект создаётся в `default`
экрана — каждый `call screen` начинает попытку заново. `renpy.Displayable` из store — подкласс с
`RevertableObject` (`renpy/exports/displayexports.py`), в отличие от внутреннего
`renpy.display.displayable.Displayable`: поля CDD откатываются, а через scope экрана попадают в сейв. Поэтому в
нём только пиклуемое: без lambda, генераторов, `Render`.

```python
def render(self, width, height, st, at):
    dt = 0.0 if self.last_st is None else min(max(st - self.last_st, 0.0), MAX_DT)
    self.last_st = st
    if self.result is None:
        self.step(dt)
    rv = renpy.Render(W, H)
    ...                                  # place/blit детей, созданных в __init__
    if self.result is None:
        renpy.redraw(self, 0)
    else:
        renpy.timeout(0)                 # иначе event() не позовут и итог не вернётся
    return rv

def event(self, ev, x, y, st):
    if self.result is not None:
        return self.result               # завершает call screen, попадает в _return
    if renpy.map_event(ev, ["K_LEFT", "pad_dpleft_press"]):
        self.left = True
        raise renpy.IgnoreEvent()        # съедаем только своё
    return None                          # Esc, колесо, F11, таймеры идут дальше
```

- Изменения полей CDD экран сам не видит: HUD рисуй внутри `render` или зови `restart_interaction()` на границах.
- Шаг модели в `render` допустим, только если он детерминирован по `st` (повторный рендер с тем же `st` ничего не
  меняет): без звука, записи в store и `renpy.random`.
- Каркас с тестами — `templates/minigame_hold_zone.rpy`; учебный образец движка — Pong в `tutorial/game/indepth_minigame.rpy`
  (с дефектами: сплошной `IgnoreEvent` глушит меню и откат, `dt` без потолка, только мышь).

### E. Рой: `SpriteManager`

Сотни однотипных объектов: каждый displayable рендерится раз за кадр, у спрайта только `x`, `y`, `zorder`.
Попадания проверять вручную в `event`; `update`/`event` — функции уровня модуля (менеджер сохраняется в сейвы).
Трансформ на отдельном спрайте уводит его с быстрого пути — вариации готовь заранее.

### Анти-модели

| Модель | Что ломается |
|---|---|
| Голый `pause` как ожидание хода (BALANCE, QTE_CIRCLE, DUNGEON, pipes) | авточтение закрывает его через ~1,5 с, пропуск — сразу; колесо откатывает попытку |
| `while` + `renpy.pause(t)` | нет контрольных точек: колесо откатывает к началу игры, за ~128 итераций лог вытесняет историю до мини-игры; быстрый пропуск крутит цикл вхолостую |
| `show screen` + голый `pause` | то же плюс click-through реплик |
| Логика в ATL `function`, `render`, `DynamicDisplayable` | движок вправе звать их при предсказании и повторно; побочные эффекты удваиваются; звук из ATL переживает `scene` |
| Драйвер модели из ATL-спрайта по `st` | `st` сбрасывается при перезапуске ATL; логика исполняется при рендере |
| Старт игры из `splashscreen` (FPE) | нет меню, сохранений, автосейва и quick menu на всю сессию |

## Уровни состояния

| Уровень | Что | Где | Сейв | Откат |
|---|---|---|---|---|
| Модель | прогресс, фаза, исход, игровое время | `default` (кортеж, словарь, объект) | да | да |
| Сессия | часы тиков, физика указателя, захват | экземпляр `NoRollback`, созданный в init | нет | нет |
| Визуал | сглаживание, дрожь, параллакс | `_fx_state` через `_fx_step` (правило `function-transform-state`) | нет | нет |
| Настройки | «Простые мини-игры», reduced motion, вспышки | `persistent` | persistent | нет |

- В сейв попадают имена, **переприсвоенные** после init, и всё достижимое из них; объект, созданный в init и только
  мутируемый, не сохраняется. Модель — только `default`.
- Кортеж, переприсвоенный целиком (`store.done += (key,)`), — простейшая гарантированно откатываемая форма.
- Часы в модели дают неверный `dt` после отката и загрузки; модель в `_fx_state` не сохраняется и не откатывается.
- Не создавай в store общие имена: параметры лейбла живут в store на время вызова (`time=` затеняет модуль
  `time`, `range=` — builtin). Префиксуй параметры и служебные переменные префиксом ядра, модуль времени
  импортируй под своим именем (`import time as qte_time`). Имена с `_` в начале зарезервированы движком (README).
- `renpy.random` — для игровых решений (повторяется при откате колесом, но не после загрузки); покадровому
  визуалу — свой `random.Random`, иначе каждый вызов пишет в лог отката и ставит контрольную точку. Воспроизводимый
  уровень — `random.Random(seed)` с сидом в `default`.

## Исход

- Возвращай значение (`return value` → `_return`) и пиши ключ исхода в `default`; `None` = «не проходил».
- Исход — ключ, а не текст: логика сравнивает ключи, в сейв идут ключи. Устаревший ключ из старых сейвов
  нормализуй при чтении (`"timeout"` → `"normal"` в замках).
- **[проект]** Исход без поражения: число попаданий, доля, `"fast"`/`"normal"`, «с ошибками»/«чисто».

## Вход и выход

- `call screen` сам прячет окно диалога (`config.window_auto_hide`). `window hide` с 8.3 не выключает
  автоуправление окном — выключает только `window auto False`.
- Экран мини-игры: `modal True`, `zorder 110` (quick menu — 100).
- Quick menu под модальным экраном виден, но не нажимается. Если он мешает (drag, цели у нижнего края), прячь его
  переменной `quick_menu` (`default` в `game/screens.rpy`): прежнее значение — в `default`, возврат на каждом
  выходе, включая пропуск; откат и загрузка возвращают её вместе с моделью. `screen quick_menu` не правь: проверка
  имени экрана замков там — частный случай.
- Модель на отдельном слое — `renpy.add_layer("…", below="screens")` при init: камера master её не трясёт,
  переходы можно вешать на один слой.
- Всё, что игра меняет вне себя (`config.perspective`, `default_mouse`, шум, громкость, лупы), запомни и верни.
  Лупы останавливай по handle из `default`.
- Отдельная точка входа (каталог сцен) должна строить кадр сама и идемпотентно: при обычном прохождении кадр
  уже показан.
- `dismiss_off()`/`dismiss_on()` блокирует только продвижение реплик (`config.say_allow_dismiss`); паузы — это
  `_dismiss_pause`, пропуск — `_skipping`/`skip_stop()`.

## Сохранение, откат, пропуск, меню

| Ситуация | Поведение движка 8.5 | Что делать |
|---|---|---|
| Загрузка посреди `call screen` | откат к началу оператора (с 8.1.2 — к оператору после последнего интерактивного, `$`-операторы между ними выполнятся заново); экран пересоздаётся со свежими `default` и новым CDD | контрольная точка на действие (модель A) или осознанный «этап заново»; **[проект]** `retain_after_load` не используется |
| Откат колесом/PgUp во время игры | `modal True` его не блокирует (стандартный keymap живёт в underlay) | по политике: как у меню (по умолчанию) или `if renpy.roll_forward_info() is None: key "rollback" action NullAction()` на время свежего раунда реального времени |
| Прокрутка вперёд после отката в пройденную игру | `RollForward` лежит в корне под слоями; экранный `key "rollforward"` его глушит, а безусловный блок `rollback` запирает игрока в игре | `key "rollforward"` не блокировать; пройденную игру узнают по `renpy.roll_forward_info()` (прежний итог; в свежем раунде и после загрузки — `None`), а не по `renpy.in_rollback()`: после загрузки оно истинно при первом показе экрана |
| Откат после исхода | исход можно переиграть, как выбор в меню; `roll_forward True` у экрана возвращает прежний результат при прокрутке вперёд | `renpy.block_rollback()` после исхода — только если владелец требует необратимость |
| Ctrl / «Пропуск» | обрабатывается до виджетов; `call screen` сам не завершается; экранный `key "skip"` не работает | без развилки — `if not renpy.is_skipping()` + `use sm_skippable_interaction`; с исходом — `skip_stop()` (или `renpy.choice_for_skipping()`), при нужде `_skipping = False` |
| Авточтение | закрывает голый `pause`; на `call screen` не действует | не строить цикл на `pause` |
| Игровое меню, H | новый контекст: слой `screens` очищен, экран мини-игры не рисуется и не тикает; `st` идёт по стенным часам | часы с потолком шага; не держать длительность раунда в разовом `timer` |
| Окно `confirm` | тот же контекст: игра рисуется и тикает под ним, ввод заблокирован | `timer … modal True` для тиков, которые должны стоять |
| Автосейв | раз в ~200 интеракций, в «простое» кадра | `$ _autosave = False` на время раунда, если сейв посреди раунда вреден |

`fix_rollback` с `call screen` работает плохо (документация `save_load_rollback`); `config.rollback_enabled` —
только init.
