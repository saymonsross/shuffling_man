# Время

## Какие часы как себя ведут

| Источник | Игровое меню, H (новый контекст) | Окно `confirm` (тот же контекст) | Особенности |
|---|---|---|---|
| `st`/`at` трансформов и CDD | идут (стенные часы) → скачок после возврата | идут | `show` того же тега обнуляет `st` (`at` сохраняется); экраны при повторном `show` своего тега `st` сохраняют |
| разовый `timer N` | дедлайн хранится в `st` → просроченный срабатывает сразу после возврата | срабатывает; `modal True` лишь откладывает до закрытия окна | новый отсчёт — только новый экран (`call screen`, показ после `hide`), ветка `if`, `for … index` с новым ключом, загрузка |
| тики `timer t repeat True` | экран не на слое → тиков нет, после возврата один тик | тикает, если нет `modal True` | пропуски не догоняются: не больше одного срабатывания за проход цикла; состояние таймера переживает `restart_interaction` и повторный `show` того же тега |
| `renpy.get_game_runtime()` | не считает | считает на границе интеракции | прирастает только в конце интеракции → внутри `call screen` стоит на месте |
| `time.perf_counter()` в `NoRollback` + потолок шага | тик не идёт → после возврата один шаг ≤ потолка | идёт, если тик-таймер без `modal` | рекомендуемый вариант; `time.monotonic()` в Python 3.12 под Windows идёт шагами по 15,6 мс |
| `u_time` шейдера | идёт | идёт | по модулю 86400 с неопределённой эпохой, float32 теряет дробную часть — только фаза циклов; шум — `u_random` |

## Рекомендуемые часы

```python
init python:
    import time as qte_time

    class QTEClock(NoRollback):
        def __init__(self):
            self.last = None

    qte_clock = QTEClock()

    def qte_dt():
        now = qte_time.perf_counter()
        last, qte_clock.last = qte_clock.last, now
        if last is None:
            return 0.0
        return min(max(now - last, 0.0), QTE_MAX_DT)   # 0.1–0.25 с
```

- `NoRollback`: откат и загрузка не возвращают старую метку; при старте раунда `last = None` даёт `dt = 0`.
- Потолок шага делает время меню, H, подвисания и перетаскивания окна не больше одного шага. Для строгого учёта —
  ещё и переякорение: запоминать `renpy.context_nesting_level()` в `config.interact_callbacks` и сравнивать в начале
  тика — после игрового меню интеракция родителя продолжается без нового колбэка.
- Никогда не считай кадры или срабатывания таймера: частота кадров зависит от монитора, `gl_framerate` и
  энергосбережения, а тики теряются.
- Раздели часы по смыслу: время показа (выдержки, подсказки) и время решения (исход) — отдельные накопители в модели.

## ATL `function` и function-трансформы

- Сигнатура `f(trans, st, at)`; число — задержка до следующего вызова (верхняя граница), `None` — «до следующей
  интеракции» у `Transform(function=)` и «перейти к следующему оператору» в ATL. `return 0` — каждый кадр, пока
  трансформ виден.
- ATL-оператор `function` на **каждом** входе (включая каждую итерацию `repeat`) сначала вызывается со `st=0`, а
  если вернул число — сразу второй раз с настоящим `st`. `function` + `repeat` с немедленным `None` → исключение
  «ATL appears to be in an infinite loop».
- Документация разрешает звать функции в любой момент, в том числе при предсказании: никаких побочных эффектов
  (звук, `renpy.random`, запись модели). Запись в `_fx_state` — под `if renpy.predicting(): return …`.
- Состояние — только `_fx_state` (правило `function-transform-state`): трансформ пересоздаётся при каждом
  `show … at`, трансформы `camera`/`show layer` — при каждом построении сцены.
- Параметры — `renpy.partial(f, key=…)`/`renpy.curry(f)(…)`, только именованные после `(trans, st, at)`; lambda и
  замыкание в показанном трансформе попадут в сейв.

## Анимация без перезапусков

- ATL в экране с меняющимися параметрами перезапускается при каждой переоценке экрана. Непрерывную анимацию
  давай function-трансформом, читающим модель, `BarValue.periodic` или CDD.
- `show` того же тега с `at` запускает эффект с нуля — непрерывность только через внешний накопитель.
- `on idle` с `repeat` перезапускается на каждой новой интеракции (урок `glow_button`).
- Анимированному шейдеру нужен источник перерисовки (`pause 0` + `repeat` или `renpy.maximum_framerate(t)`),
  иначе Ren'Py опускается до 5 FPS. Держи перерисовку только пока эффект виден.

## Шкалы и полосы

- Шкала-таймер без кода: `bar value AnimatedValue(1.0, 1.0, t, 0.0)` — от старого значения к новому за `t`;
  при частой смене цели прыгает к прошлой цели, а не к текущему положению.
- Свой `BarValue`: `periodic(st)` зовётся на **каждом** рендере бара (документация говорит «раз за интеракцию» —
  код 8.5 другой) → «полоска силы» без перезапусков экрана.
- Отображение модели — `StaticValue(value, range)` (без фокуса).
- Полоса из модели в каркасе QTE — function-трансформ ставит `xzoom` по остатку времени.
- Анти-паттерн: `timer 0.05 repeat True` + `IncrementScreenVariable` — пересчёт всех экранов 20 раз в секунду.

## Честность окон

- Вступление: покажи задание 0,6–0,8 с без отсчёта и игнорируй ввод — «хвост» клика прошлой реплики не
  сорвёт раунд.
- Сверяй попадание с тем, что игрок видел: позицию из последнего отрисованного кадра (кэш в `_fx_state` под ключом
  раунда) или из той же функции времени, что рисует объект.
- `ease` у маятника быстрее в центре — сложность зоны зависит от её положения (BALANCE).
- Проверь достижимость расчётом: окно попадания в мс при 60 Гц, требуемые клики в секунду (финал прототипа требовал
  ~7,9 клика/с — практически недостижимо).
- После мэша дай «остыть»: игнорируй ввод или `renpy.pause(t, hard=True)` — иначе хвост кликов пролистает реплики.
  Под модальным экраном таймированная пауза держится (`config.modal_blocks_pause`) — `renpy.pause(t, hard=True, modal=False)`.
- Параметры сложности — аргументы раунда/фразы; «Простые мини-игры» — медленнее, шире, без таймера.

## Звук и музыка во времени

- Звук, запущенный внутри интеракции, стартует на аудиотике (до ~50 мс) плюс буфер (~43 мс на desktop, ~171 мс в
  web). Между интеракциями — на следующей интеракции или через `renpy.music.pump()`.
- Позиция трека — `renpy.music.get_pos(channel)`; `None` и при позиции 0. В проекте звук идёт через пул каналов:
  канал — первый элемент handle `(канал, серия)` из обёрток.
- Контракт фразы для пианино (из прототипа): `(фраза, окно, параметры) → (исход, прошедшее время)`; подстройка к
  такту — от одного источника времени (позиция трека или часы фразы), не от `time.time()` в разных местах.
