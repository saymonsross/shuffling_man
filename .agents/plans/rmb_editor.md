# RMB Editor: Shift+ПКМ в игре → промпт Claude во вкладке VS Code — план

**Цель:** `Shift`+правый клик по любому объекту в dev-запуске ставит кадр на паузу и открывает поле ввода; введённый промпт вместе с контекстом клика и брошенными в окно файлами попадает в новую вкладку чата Claude Code в VS Code.

**Стек:** Ren'Py 8.5.3 (screen language, `renpy.Displayable`, контексты, pygame_sdl2 / SDL 2.0.20), URI-обработчик расширения Claude Code для VS Code, Windows.

## Проблема

Правка сцены сейчас идёт в два приёма: автор видит в игре, что не так, переключается в VS Code и словами описывает Claude, о каком спрайте, кнопке и моменте сценария речь. Описание неточное, а файл и строку Claude ищет сам. Звук подключается похожим образом: путь к WAV копируется руками в чат вместе с описанием момента.

Нужен инструмент, который превращает клик в игре в готовый запрос: что под курсором, где это в коде, где стоит сценарий, как выглядит кадр — плюс текст автора и приложенные файлы.

## Требования

- R1. **Shift+ПКМ открывает ввод.** В dev-запуске отпускание правой кнопки с зажатым `Shift` в сцене, в мини-игре с modal-экраном, в главном и в игровом меню открывает поле ввода у курсора. ПКМ без `Shift` работает штатно: игровое меню, `alternate` кнопок, «Нет» в диалогах подтверждения. `Shift`+ПКМ при открытом поле второе поле не открывает. После закрытия поля сам жест ничего больше не вызывает: игровое меню не открывается, реплика не пролистывается.
- R2. **Кадр на паузе.** Пока поле открыто, игра стоит так же, как под игровым меню: сценарий не продвигается, экраны игры и их таймеры, спрайты и камера сцены не исполняются, ввод до игры не доходит. Сквозные эффекты слоёв (`config.layer_transforms`: параллакс, постеризация) продолжают считаться, как под игровым меню. На экране — застывший кадр момента клика. Звук продолжает играть. После закрытия поля игра продолжается с той же строки сценария; ожидания по времени и анимации ведут себя как после игрового меню — будто время паузы прошло: `pause` с истёкшим таймаутом завершается сразу, ATL оказывается дальше по времени.
- R3. **Контекст клика.** Запрос содержит:
  - координаты клика в виртуальных пикселях 1920×1080, размер скриншота и координаты клика в пикселях скриншота;
  - спрайты сцены, чей нарисованный прямоугольник накрывает точку, — с учётом `camera`-трансформов и параллакса, без учёта прозрачности и перекрытия; в главном и игровом меню спрайты не выводятся: тег с атрибутами, слой, pos/anchor/rotate/zoom из кода и строки `show`/`scene` этого тега (файл:строка), строки текущего файла сценария помечены;
  - элементы экранов под курсором: имя экрана, тип и описание displayable, размер, файл:строка определения (у элементов, для которых движок её хранит);
  - позицию сценария (файл:строка) и лейбл базового контекста игры, список показанных экранов; в главном меню позиции сценария нет, служебные лейблы (с `_`) не выводятся;
  - скриншот кадра без поля ввода.
  Пути — относительно корня проекта, через `/`. Элементы из `renpy/common`, из `game/dev/**` и служебных полноэкранных экранов (виньетка, вспышка) в контекст не попадают; сам экран элементом не считается — от него берётся только имя. Клик по пустому месту даёт запрос без спрайтов и элементов.
- R4. **Поле ввода.** Многострочное: `Shift+Enter` — перенос; принимает кириллицу и вставку из буфера (`Ctrl+V`; многострочная вставка склеивается в одну строку — ограничение `input`). Над полем — одна строка о том, что поймано (`prologue_hand_right · game/0_prologue/prologue_scene.rpy:226`). `Enter` отправляет, `Esc` закрывает без отправки. Пока поле открыто, клавиши и клики не вызывают ни встроенные действия Ren'Py, ни dev-инструменты: `Tab`, `PageUp`/`PageDown`, `F1`–`F12`, `Alt+буква`, колесо, клик мимо поля.
- R5. **Отправка.** `Enter` открывает новую вкладку чата Claude Code в VS Code; в её поле ввода подставлены текст автора, строка о пойманном объекте, список приложенных файлов и путь к файлу запроса. Текст из поля доходит символ в символ: переносы, `+`, `&`, `%`, кириллица. Файл запроса всегда содержит всё: текст, сводку, вложения, контекст. Если ссылка длиннее бюджета, в неё попадает только указание прочитать файл запроса — без текста, сводки и вложений. Пустой текст допустим.
- R6. **Перетаскивание.** Файл, брошенный из Проводника на окно игры, прикрепляется к запросу: при открытом поле добавляется в список над ним, при закрытом — ставит кадр на паузу и открывает поле с этим файлом и контекстом без координат, спрайтов и элементов (позиция сценария, экраны, скриншот). Несколько файлов копятся; каждый можно убрать. В запрос уходят абсолютные пути; сами файлы не копируются и не меняются.
- R7. **Обратная связь.** После отправки поле закрывается, игра продолжается, и уже в игре `renpy.notify` сообщает «отправлено в VS Code». Если открытие ссылки завершилось исключением (протокол `vscode://` не зарегистрирован), поле остаётся открытым с текстом ошибки, набранное не теряется.
- R8. **Только dev и вне игрового состояния.** Весь код — в `game/dev/**`; без `config.developer` не регистрируются ни экран инструмента, ни событие перетаскивания. Поле, черновик и вложения не попадают в сейвы и rollback.
- R9. **Перезагрузка скриптов не теряет черновик.** После автоперезагрузки при открытом поле (сохранён сценарный `.rpy`) оно снова открыто с тем же текстом, вложениями, контекстом и застывшим кадром. Позиция игры под полем восстанавливается так же, как при обычной перезагрузке скриптов.
- R10. **Тесты не трогают VS Code.** Под `renpy.is_in_test()` настоящая ссылка не открывается никогда; открыватель, корень папки запросов и проверка `Shift` подменяются и сбрасываются после каждого теста.
- R11. **Папка запросов не копится.** Хранятся последние 10 запросов (скриншот в размере окна — несколько мегабайт); при создании нового удаляются старые папки этого же формата имени и ничего кроме них. `Esc` не оставляет папки запроса. Папка вне `game/`, не в git и не в сборке.

## Решения

| # | Решение | Почему | Отклонено |
|---|---|---|---|
| D1 | Транспорт — ссылка `vscode://anthropic.claude-code/open?prompt=<текст>`: новая вкладка чата с подставленным промптом; отправка — `Enter` в VS Code | Автор хочет видеть работу Claude в VS Code, в новой вкладке. Проверено на расширении 2.1.284: вкладка открывается, текст подставлен и не отправлен, ссылка в 3308 символов доходит целиком | Фоновый `claude -p` из игры — работа не видна в VS Code, нужны заранее заданные права, панель статуса и управление автоперезагрузкой. Слежение открытой сессии за папкой запросов — живёт, только пока сессия взведена. Имитация `Enter` в окне VS Code — зависит от фокуса и таймингов. Параметр `session=<uuid>` для общей сессии — неизвестный id уводит расширение в ветку «сессия не найдена» |
| D2 | В ссылке — текст автора и краткая сводка; полный запрос и скриншот — файлами в `.rmb_editor/<id>/` в корне проекта | Ссылка не переносит картинку; короткий промпт читается в поле ввода VS Code; файлы внутри рабочей папки Claude читает без запроса разрешений | Весь контекст в ссылке — длина и нечитаемость. Системный temp — чтение вне рабочей папки требует подтверждения. Папка внутри `game/` — автоперезагрузка и попадание в сборку |
| D3 | Перехватчик — `renpy.Displayable` в экране из `config.always_shown_screens` на слое `top`; ловит отпускание ПКМ при зажатом `Shift` и `DROPFILE`, остальное пропускает. `Shift` читается из состояния клавиатуры подменяемой функцией. Обработав жест или бросок, перехватчик поднимает `renpy.IgnoreEvent` | Такой экран есть в каждом контексте, включая меню и контекст поля. Слой `top` получает события раньше слоёв сцены и мини-игр (`lockgame`, `forever`, `screens`) при любом порядке `config.layers`, раньше кнопок с `alternate` и underlay-keymap. Displayable несёт координаты клика. Keysym `mouseup_3` у `game_menu` и `button_alternate` не уточняет `Shift` и совпадает и с этим жестом — без `IgnoreEvent` после закрытия поля открылось бы меню, а возврат значения завершил бы взаимодействие игры. `ev.mod` события мыши устаревает при смене фокуса окна, поэтому `Shift` берётся из клавиатуры; в тестах проверка подменяется (D12) | Экран на слое `screens` — слои выше получают событие первыми, zorder между слоями не действует. `key "shift_mouseup_3"` — не даёт координат события и не ловит `DROPFILE` (это не keysym). ПКМ без модификатора — отнимает у игры меню, `alternate` и «Нет» в подтверждениях, требует выключателя и списка исключений |
| D4 | Поле ввода живёт в новом контексте (`renpy.invoke_in_new_context`, как инспектор Ren'Py): в нём очищены все слои, включая слои сцены, и сброшены их `camera` и `show layer`, фоном показан скриншот момента клика | Это штатная пауза движка, та же, что под игровым меню: базовый контекст не исполняется, его экраны и таймеры не работают, события до него не доходят (R2). Очистка только слоёв по умолчанию оставила бы в контексте поля копии `master`, `lockgame`, `forever`: под фоном продолжали бы исполняться спрайты и таймеры экранов, показанных на этих слоях. Очистка слоя не сбрасывает его `camera_list`: без явного сброса function-трансформы камеры работали бы над пустым слоем и двигали своё состояние в `_fx_state`. `config.layer_transforms` — глобальная настройка, в контексте поля она остаётся | Поле поверх идущей игры (показанный или always-shown экран) — паузы нет; чтобы игра не получала ввод, нужны modal, поглотитель и всё равно остаётся прямой опрос мыши параллаксом и мини-играми. `_clear_layers=False` — экраны игры переезжают в новый контекст живыми: таймеры идут, кнопки нажимаются |
| D5 | В экране поля есть displayable-поглотитель: `renpy.IgnoreEvent` на события клавиатуры, кнопок и колеса мыши, не обработанные полем; `DROPFILE`, события времени и перерисовки он пропускает. Взаимодействие поля идёт с обычным underlay. Порядок на слое `top`: зерно (zorder 0) → экран поля с фоном → always-shown экран перехватчика | Поглотитель закрывает и контроллеры хоткеев F6–F12 (always-shown экраны показываются и в контексте поля), и underlay (`game_menu`, `hide_windows`, `reload_game`, `rollback`; просочившийся запрос отката движок исполнил бы после возврата). Перехватчик выше поля — получает `DROPFILE` и повторный жест первым | `suppress_underlay` — под ним исполнитель тестов Ren'Py не работает, а хоткеи dev-инструментов всё равно остаются. Только `modal` — `IgnoreLayers` доходит до underlay |
| D6 | Попадание по спрайтам — по дереву отрисовки под точкой (прямоугольник рендера), сопоставленному с `renpy.scene_lists()` по идентичности displayable; трансформ и строки кода — функциями Position Tuner | Дерево отражает кадр как он нарисован, с камерой и параллаксом; Position Tuner уже умеет отдавать значения «как в коде» и искать строки `show` | Попадание по `pt_bounds` — bbox в базовых координатах, в сценах с `camera at` расходится с картинкой (ограничение описано в README Position Tuner) |
| D7 | Элементы экранов — из того же дерева отрисовки, по `_location` | Мини-игры и UI целиком живут в экранах; дерево инспектора даёт файл и строку оператора экрана | Поиск по `renpy.get_screen` и id виджетов — у большинства элементов нет id |
| D8 | Данные запроса (признак «поле открыто», черновик, вложения, контекст, папка запроса) — в `renpy.session` простыми типами; признак «контекст поля сейчас исполняется» — module-level. Если первый признак есть, а второго нет, перехватчик заново открывает поле — из обработчика события, не из кода экрана и не во время фазы перезагрузки. Признак «поле открыто» снимается при любом выходе из контекста поля, кроме перезапуска движка | `renpy.session` переживает перезагрузку скриптов и не входит в сейвы и rollback; module-level признак при перезагрузке сбрасывается сам — по расхождению двух признаков видно, что поле надо восстановить (R9). Снятие признака при выходе по ошибке не даёт полю открываться снова и снова поверх экрана ошибки | Всё в module-level `python_dict` — черновик теряется при автоперезагрузке, то есть в основном сценарии: Claude правит `.rpy`, автор набирает следующий запрос. `default`-переменные — попадают в сейвы и rollback |
| D9 | Отправка и отмена завершают собственное взаимодействие поля: `Enter` — через свойство `action` у `input`, `Esc` — клавишей экрана | Взаимодействие принадлежит контексту поля, игра под ним не затрагивается; при заданном `action` `input` не передаёт `Enter` дальше | `InputValue.enter()` без `action` — `None` пропускает `Enter` дальше по цепочке |
| D10 | Бросок файла означает «прикрепить», не «сюда» | Событие SDL 2.0.20 не несёт координат; когда окно не в фокусе мыши, движок подставляет событию `(-1, -1)` | Привязка места к точке броска — положение курсора в этот момент недостоверно |
| D11 | Ссылка открывается через `os.startfile`, на время вызова `ELECTRON_RUN_AS_NODE` убирается из `os.environ` и возвращается после | Проверенный путь: так открылась ссылка в 3308 символов; у `os.startfile` нет параметра окружения | Запуск `Code.exe --open-url` через `subprocess` — требует искать путь к `Code.exe`; `cmd /c start` — портит `&` и `%` в ссылке |
| D12 | Открыватель ссылки, корень папки запросов и проверка `Shift` подменяются через отдельный module-level словарь | Тесты проверяют собранную ссылку и файлы, не открывая VS Code, и открывают поле кликом независимо от состояния клавиатуры SDL (R10); подмены не должны переживать перезагрузку скриптов, поэтому лежат не в `renpy.session` | Проверка `is_in_test()` внутри логики сборки — тест не увидел бы итоговую ссылку |
| D13 | Скриншот пишется в папку запроса сразу при клике, он же — фон поля; `Esc` удаляет папку | Кадр без поля можно снять только до его показа; один файл служит и Claude, и застывшему кадру; запись в файл не трогает миниатюру следующего сейва | `renpy.screenshot_to_bytes` — перезаписывает `interface.screenshot_surface`, кадр станет миниатюрой сейва |
| D14 | В Dev Hub — строка инструмента с подписью «Shift+ПКМ»; клик закрывает хаб и открывает поле с контекстом без точки после кадра, на котором хаба уже нет | Dev Hub — единая точка входа и шпаргалка клавиш dev-инструментов; скриншот — последний отрисованный кадр, панели хаба на нём быть не должно | Инструмент без записи в хабе — о жесте можно узнать только из README |

## Контекст предметной области

### Ссылка расширения Claude Code

- Обработчик (`extension.js`): путь `/open`, параметры `prompt` и `session`; вызывает `claude-vscode.primaryEditor.open(session, prompt)` → `createPanel` → новая вкладка. В webview промпт проходит через `setInputText` — только подстановка.
- Кодирование: `urllib.parse.quote(text, safe="")`. Расширение разбирает запрос через `URLSearchParams`, где `+` означает пробел, поэтому `quote_plus` недопустим.
- Протокол `vscode://` зарегистрирован на `Code.exe --open-url -- "%1"`.
- **Ловушка окружения:** если процесс унаследовал `ELECTRON_RUN_AS_NODE=1` (любой потомок extension host VS Code), `Code.exe` запускается как Node и завершается с `bad option: --open-url`, а `os.startfile` исключения не даёт. Такой сбой игра обнаружить не может — поэтому переменная убирается заранее (D11), а R7 обещает сообщение только для сбоев с исключением.
- Ссылка приходит в последнее активное окно VS Code. Если открыто несколько проектов, вкладка может появиться в чужом окне — ограничение фиксируется в README.
- Проверенные значения для тестов: строка `"ТЕСТ\nстрока 2 + плюс & амперсанд"` после `quote(..., safe="")` и `urllib.parse.unquote` совпадает с исходной; ссылка длиной 3308 символов (587 символов кириллицы) доходит целиком. Бюджет `RMB_URL_MAX` — 3000 символов.

### Контексты и пауза

- `renpy.invoke_in_new_context(callable, _clear_layers=True)` (`renpy/game.py`) создаёт контекст поверх текущего и вызывает функцию; предназначена для вызова из обработчика события. При `_clear_layers=True` очищаются `config.context_clear_layers` (`screens`, `top`, `bottom`); остальные слои, включая `master`, копируются в новый контекст и продолжают исполняться в нём. `_clear_layers` принимает и список слоёв. Экраны 7dots `show_s` и `show_forever` показываются на `master` и `forever`.
- Образец — инспектор (`renpy/common/_developer/inspector.rpym`): `renpy.show_screen(..., transient=True)` и `renpy.ui.interact(mouse="screen", type="screen", suppress_overlay=True, suppress_underlay=True)`. Его `suppress_underlay` перенимать нельзя: исполнитель тестов не работает, пока `interface.suppress_underlay` установлен (`renpy/test/testexecution.py`, `execute`).
- Контекст из обработчика события открывают и штатные действия (`ShowMenu` из `Button.event`); после возврата взаимодействие базового контекста перезапускается. Идущий переход при входе в контекст отменяется.
- always-shown экраны показываются заново в каждом взаимодействии любого контекста (`screen.py`, `show_overlay_screens`), в том числе в контексте поля.
- Автосохранение при вложенном контексте пропускается (`loadsave.py`); игровое меню из контекста поля недостижимо.
- Перезагрузка скриптов из вложенного контекста (`_save_reload_game`, `renpy/common/00keymap.rpy`) сохраняет базовое состояние, делает utter restart и возвращает игру в базовый контекст; контекста поля после неё нет, `renpy.session` цел. Если в сцене ещё не было ни одной точки отката, движок после перезагрузки уходит в главное меню — с открытым полем и без него одинаково.
- Время под паузой не останавливается: `pause` и экранные `timer` отсчитываются от исходного начала, ATL — от времени показа, часы движка (`core.get_time`) сдвинуть нельзя. Поэтому после возврата истёкшие ожидания завершаются сразу, а анимации оказываются дальше — как после игрового меню. Мини-игра замков уже переякоривает своё время при смене контекста (`context_nesting_level()` в `interact_callbacks`).
- `renpy.notify` показывает экран в текущем контексте — вызванное внутри контекста поля уведомление исчезнет вместе с ним.
- Фаза перезагрузки: между сохранением и загрузкой в `renpy.session` лежит `_reload_slot`, в это время идёт взаимодействие «Reloading game...» с always-shown экранами. Главное меню — само вложенный контекст; после перезагрузки движок может восстановить игровое меню.
- Картинку вне `game/` движок по пути не загружает; фон из файла запроса строится из байтов файла (`im.Data` в `renpy/display/im.py`). Скриншот снят в размере окна и показывается растянутым на 1920×1080.

### События Ren'Py

- Порядок раздачи (`renpy/display/core.py`): `behavior.skipping(ev)` → `focus.mouse_handler` → `root_widget.event` (слои сверху вниз, внутри слоя — от большего zorder к меньшему, внутри экрана — от последнего ребёнка к первому) → `focus.key_handler`.
- `game_menu` (`mouseup_3`) живёт в underlay и получает событие последним; `alternate` кнопки срабатывает в `Button.event` по `button_alternate` = `mouseup_3`.
- `IgnoreLayers` (его поднимает modal-экран) останавливает только слои и доходит до underlay; `IgnoreEvent` останавливает обработку целиком.
- Движок проставляет `ev.mod` на каждое событие, включая мышиные, но сбрасывает модификаторы SDL при смене фокуса окна, и сохранённое значение устаревает; состояние `Shift` читать из клавиатуры (`pygame_sdl2.key.get_mods()`). Keysym `mouseup_3` без `shift`/`noshift` совпадает с ПКМ при любом состоянии `Shift`.
- Что `input` съедает сам: печатные клавиши (в том числе с `Shift`), редактирование, `input_enter`, `input_next_line`. Что он пропускает: `KEYDOWN` с левым `Alt` без unicode, функциональные клавиши, `Tab`, `PageUp`/`PageDown`, события мыши.
- Кнопка под курсором мыши считается в фокусе, а `button_select` включает `K_RETURN` без уточнения `Shift`: `Enter` и `Shift+Enter` нажимают такую кнопку, если она получает событие раньше поля ввода.
- Оператор `input` принимает свойства `action`, `value`, `multiline`, `copypaste` (`sl2/sldisplayables.py`). `input_enter` при заданном `action`: `run(action)`; результат не `None` завершает взаимодействие, `None` → `IgnoreEvent` (`behavior.py`, `Input.event`).
- Вставка (`input_paste`) отбрасывает символы с кодом меньше 32, включая `\n`.
- `behavior.skipping(ev)` вызывается до displayable, `Ctrl` включает промотку; от этого защищает проверка `text_rect`, который выставляется при отрисовке `input`. Поведение `Ctrl+V` и `Ctrl+C` при открытом поле проверить вживую.
- Слои проекта: `config.layers` = `master`, `transient`, `lockgame` и `forever` (оба вставлены перед `screens`), `screens`, `overlay`; поверх — `top` (`config.top_layers`). На `top` живут Dev Hub, FX Tuner, Font Picker и экран зерна `fx_noise_screen` (always-shown — он будет и в контексте поля, фон должен лежать выше него); контроллеры хоткеев — на `screens` с zorder 1100.
- Ren'Py блокирует стандартные события SDL, которых нет в `enabled_events`; исключение — типы из `config.pygame_events` (список; читается в `Interface.post_init`, движок только блокирует и никогда не разблокирует). `DROP*` в `enabled_events` нет. Если инструмент появился при запущенной игре, бросок может заработать только после полного перезапуска — проверить и записать в README.
- `pygame_sdl2.DROPFILE` = 4096. В исходниках pygame_sdl2 событие создаётся как `EventType(type, file=<utf-8 путь>, window_id=...)`; в SDK модуль бинарный, поэтому имя атрибута `file` подтверждается живой проверкой. `pygame_sdl2.event.post` молча отбрасывает событие заблокированного типа, поэтому дошедшее посланное событие доказывает разблокировку типа, но не доставку ОС → SDL. `DROPBEGIN`, `DROPCOMPLETE`, `DROPTEXT` не нужны.
- Для событий не от мыши `x, y` — последнее известное положение курсора, а при `not mouse_focused` — `(-1, -1)`.
- Язык тестов: `click button 3 pos (x, y)`, `pause`, `keysym "K_RETURN"`, `keysym "shift_K_RETURN"`; `type "текст"` набирает только символы US-раскладки — кириллицу и переносы в тестах задавать через состояние, а не набором. Исполнитель тестов вызывается из каждого взаимодействия, в том числе во вложенном контексте.

### Сбор контекста

- Дерево под точкой: `renpy.game.interface.surftree.main_displayables_at_point(x, y, config.layers)` → список `(depth, width, height, displayable)`; слой `top` в `config.layers` не входит и не обходится, попадание — по прямоугольнику рендера, без альфы. Так его читает инспектор, описание элемента — `_inspector_repr(d)`. Контекст собирается в обработчике события, до входа в контекст поля.
- Спрайт → тег: записи `renpy.scene_lists().layers[layer]` несут `tag` и `displayable` (образец — `_pt_live` в Position Tuner); тег попал под точку, если его displayable есть в дереве.
- `d._location` — `(файл, строка)`; задаётся на главном displayable оператора экрана (`renpy/sl2/slast.py`). У `Text` внутри `textbutton`, детей `add` и обёрток `at` его нет — такие элементы описываются по ближайшему предку с `_location`. У `ScreenDisplayable` это место определения экрана, имя — `d.screen_name[0]`; он рендерится на весь экран, поэтому под любой точкой оказываются все показанные экраны. Always-shown экраны `fx_vignette_screen` и `fx_flash_screen` (`game/common/`) лежат на слое `screens` с полноэкранным `add` и без исключения попали бы в каждый запрос.
- Position Tuner (`game/dev/position_tuner/`): `pt_showing()` — теги с атрибутами по всем слоям сцены, `pt_scene_state(name)` — pos/anchor/rotate/zoom/alpha «как в коде», `_pt_rpy_files()` — абсолютные пути сценарных `.rpy` без `dev`, `tl`, `libs`, `_pt_show_matches(line, t)` — совпадение строки `show` с тегом (`t` — любой объект с `.name`). Строку `scene <тег>` эта функция не распознаёт; фон должен находиться тем же правилом сопоставления тега и атрибутов.
- Опорная строка для теста: `game/0_prologue/prologue_scene.rpy` содержит `show prologue_hand_right at placed((1358, 468))`. Сцены с камерой: `prologue_scene.rpy` (`camera at camera_push(...)`), `chapter_1_scene_1.rpy`.
- `renpy.get_filename_line()` в контексте меню указывает на `renpy/common`; позиция сценария берётся из базового контекста игры. На Windows путь может прийти с `\` — нормализовать (образец нормализации — `game/common/interactions.rpy`).
- `renpy.screenshot(path)` сохраняет последний отрисованный кадр в размере окна, а не 1920×1080; вызванный в обработчике события до показа поля, он даёт кадр без поля.
- `renpy.session` — словарь, переживающий перезагрузку скриптов; его уже использует `game/dev/testcases.rpy`.

### Проверка 7dots

В `7dots-reference` нет средств для перехвата мыши, ввода текста, буфера обмена и обмена файлами с ОС; `shot()` снимает миниатюру для сейва, а не файл. Инструмент ничего из 7dots не дублирует. Перед написанием `.rpy` исполнитель открывает skill `7dots-reference` (правило `AGENTS.md`).

## Ограничения

- Имена файлов, лейблов и констант — по конвенциям `AGENTS.md`; параметры инструмента — `define -30` константами с префиксом `RMB_` (zorder экранов, бюджет ссылки, число хранимых запросов, список экранов, исключаемых из контекста клика (R3), лимиты строк в файле запроса).
- Имя слоя в экранах записано литералом `"top"`: оно вычисляется при объявлении экрана, раньше любых `define`.
- Строки интерфейса dev-инструментов намеренно не локализуются (как в Dev Hub и Position Tuner); шрифт панели — `DejaVuSans.ttf`, не игровой.
- Пиксельные позиции — `int`; положение поля вычисляется через `int(round(...))`, поле не выходит за край экрана.
- Комментарии — только неочевидные инварианты (`.agents/rules/comments.md`): зачем новый контекст и фон-скриншот, зачем поглотитель, ловушка окружения, два признака состояния.
- Сценарные `.rpy` инструмент только читает и ничего не записывает в `game/`; из них в запрос попадают лишь строки `show`/`scene`. Текст элементов экрана берётся с кадра — тот, что виден игроку. Шаблон промпта не повторяет правила `AGENTS.md`: сессия VS Code загружает их сама.
- Position Tuner не переписывается: его функции вызываются как есть.
- Данные инструмента в `renpy.session` — только `str`, числа, `list`, `dict`, `tuple`: объекты классов из store не переживают перезагрузку скриптов.
- Временные тестовые файлы и прогоны — в копии проекта в scratchpad с `--savedir`. Правка тестовых файлов в живой `game/` при открытой игре роняет автоперезагрузку («defined twice») — после неё нужен полный перезапуск игры.
- Результаты существующих тестов не меняются: экран-перехватчик активен и под тестами.

В `README.md` обновлён заголовок раздела dev-инструментов и добавлен подраздел.

**Ограничения:** контекст клика и скриншот собираются в обработчике события до входа в контекст поля; в панели кнопки вложений стоят выше поля ввода, чтобы `Enter` доставался полю, а не кнопке под курсором; zorder экрана поля и экрана перехватчика — две константы, порядок из D5; поглотитель получает события последним (он первый ребёнок экрана: события раздаются от последнего ребёнка к первому, клавиша Esc объявляется после него); признак «контекст поля исполняется» снимается при любом выходе из контекста, в том числе по исключению; папка запроса удаляется только по `Esc`, не при выходе по ошибке; `renpy.notify` вызывается после возврата из контекста; `MOUSEBUTTONDOWN` правой кнопки перехватчик не трогает.

**Риск: высокий.** Вход в новый контекст из обработчика события проверить в каждом из четырёх мест R1 и из броска файла. Очистку всех слоёв в контексте поля проверить на сцене с камерой и на мини-игре замков; если она что-то ломает при возврате — вернуться к очистке по умолчанию и записать в README, что сцена под фоном продолжает исполняться. Возврат после долгой паузы в мини-игре с таймером — поведение должно совпадать с возвратом из игрового меню; расхождение фиксировать, а не чинить мини-игру. Восстановление поля после автоперезагрузки и конфликт `Ctrl` с промоткой при `Ctrl+V` — проверить вживую. Если окно не 16:9, скриншот может содержать поля — проверить фон и пересчёт координат. Доставка настоящего броска из Проводника автоматикой не проверяется.
